# Code of Conduct

Wulfpack Forge is a small community project. The standard is simple: contribute in a way that makes the project safer, clearer, and easier to work on.

## Expected behavior

Participants are expected to:

- treat other people with respect;
- critique code and ideas rather than people;
- provide enough context for others to understand a problem;
- accept correction when evidence shows an assumption was wrong;
- avoid harassment, discrimination, threats, and personal attacks;
- avoid publishing private or sensitive information;
- keep technical disagreements focused on the work;
- respect licensing, attribution, and ownership boundaries.

## Unacceptable behavior

The following is not acceptable in project spaces:

- harassment or intimidation;
- discriminatory or demeaning language;
- sexualized attention or imagery directed at participants;
- deliberate disruption of issues or reviews;
- repeated bad-faith argument after a maintainer decision has been explained;
- doxxing or disclosure of private information;
- malicious code, intentionally destructive test data, or misleading security reports.

## Technical disagreement

Disagreement is normal. For this project, evidence wins.

When contributors disagree about behavior, compatibility, or safety, prefer:

1. reproducible tests;
2. current source behavior;
3. documented game/version evidence;
4. repository governance and roadmap decisions.

The loudest opinion does not acquire extra technical accuracy by volume.

## Enforcement

The repository maintainer is responsible for interpreting and enforcing this code within project spaces. Responses may include editing or removing content, closing or locking discussions, declining contributions, or restricting participation.

Serious safety or harassment concerns should be raised privately with the repository maintainer when possible.

## Scope

This code applies to repository issues, pull requests, reviews, discussions, and other spaces where someone is representing the Wulfpack Forge project.
